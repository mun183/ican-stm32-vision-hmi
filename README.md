## 作品简介

“衣履净界”面向家庭入户场景，将衣物护理、鞋履存换和随身物品处理整合到同一套设备中。作品方案采用模块化结构，结合机械传动、气流循环、视觉感知及语音与触控交互，减少用户在多台设备之间切换的操作。

本仓库提供控制与交互部分的工程文件，供评审查看软件实现和在配套设备上复现。整机结构、硬件电路与演示效果由应用方案、硬件设计文档、实物照片和作品视频配套说明。

## 场景与差异化设计

**围绕入户流程组织功能。** 作品从用户进入家门后的换鞋、衣物处理和随身物品放置出发，将多项护理需求纳入同一套设备，强调连续操作和空间整合。

**将 AI 感知放到具体任务中。** 视觉模块采用目标检测，完成图像采集、模型推理、结果可视化与串口信号输出，为设备的感知层提供实现基础。应用方案围绕衣物污渍识别与鞋履识别安排自动化处理场景。

**以结构与电控配合场景。** 方案将平面传动机械臂、衣物悬浮腔体、鞋履存换装置和循环风道组合设计，采用多板协同电控架构，把运算控制、供电及外设接口分层组织。

## 技术路线

| 层级 | 技术与实现内容 | 场景作用 |
| --- | --- | --- |
| 感知层 | 摄像头采集、YOLOv5 推理、检测框与置信度显示、串口信号输出 | 提供目标感知与可视化反馈 |
| 控制层 | STM32F407 主从控工程、串口通信、定时任务与外设驱动 | 组织设备命令与执行控制 |
| 执行层 | 机械传动、风机、光电检测及护理相关执行模块 | 承接衣物、鞋履与随身物品处理流程 |
| 交互层 | 陶晶驰串口屏、语音模块接口 | 提供触控与语音操作入口 |

视觉推理在设备端执行，控制程序与人机界面分别保留独立工程，便于按模块查看、部署和演示。

## 应用与落地规划

| 用户需求 | 作品的设计回应 |
| --- | --- |
| 入户时需要依次处理鞋履、衣物和随身物品 | 将连续操作组织为一体化护理流程 |
| 多台单功能设备占用空间、增加操作步骤 | 通过模块化结构集中配置功能 |
| 不同使用者的操作习惯存在差异 | 结合语音与触控入口，提供多种交互方式 |
| 不同住宅空间与功能需求需要适配 | 以功能模块为基础规划选配与场景扩展 |

推广规划优先面向家庭住宅、公寓等入户场景，在原型展示基础上推进模块标准化、安装维护与使用体验优化。商业模式可围绕整机销售、功能模块选配及维护服务展开，后续根据用户需求拓展智能家居联动与不同安装形态。

## 运行环境

| 模块 | 环境要求 |
| --- | --- |
| STM32 | STM32F407 配套控制板；Keil MDK；工程记录的编译器为 ARMCC 5.06 update 6 (build 750)，器件包为 `Keil.STM32F4xx_DFP.2.12.0` |
| 视觉 | 支持 MaixPy v4、`maix.nn.YOLOv5` 和 `.cvimodel` 的 MaixCAM / MaixCAM-Pro 环境；MaixVision；配套摄像头与显示屏 |
| 串口屏 | 与原工程设备型号匹配的陶晶驰串口屏及兼容的串口屏编辑软件 |

视觉程序使用 MaixPy 接口，模型以 `.mud` 描述文件与 `.cvimodel` 推理文件配套部署。平台与工具说明参见 [MaixPy 官方文档](https://wiki.sipeed.com/maixpy/en/)，具体操作见[运行与复现指南](docs/RUNNING.md)。

建议将作品视频与现场演示按以下顺序组织，每个环节对应一个明确的评审观察点：

3. **交互操作：** 展示串口屏页面、触控指令及语音操作，使操作过程清晰可见。
4. **执行过程：** 结合实物展示机械机构、风机和相关护理模块的操作流程。
5. **技术与价值：** 用简洁的结构图和工程入口说明软硬件分工，再回到家庭使用场景及模块化推广规划。
