# 运行与复现指南

本指南介绍“衣履净界”智能鞋衣净护系统的工程入口、开发环境与部署流程。三个工程目录保留原始代码，评审可结合配套原型、应用方案和作品视频查看实现。

## 获取源码

从[仓库首页](https://github.com/mun183/ican-stm32-vision-hmi)选择 `Code > Download ZIP` 并解压，或通过 Git 获取：

```bash
git clone https://github.com/mun183/ican-stm32-vision-hmi.git
cd ican-stm32-vision-hmi
```

HMI 工程约 51 MiB，下载或克隆时请保留完整文件。模型二进制和 HMI 工程需使用对应工具加载。

## STM32 主从控

### 开发环境

- 控制芯片：`STM32F407VGTx`，与硬件材料中的 STM32F407VGT6 对应。
- IDE：Keil MDK / uVision。
- 原工程编译器：ARMCC `5.06 update 6 (build 750)`，工程配置为 `uAC6=0`。
- 原工程器件包：`Keil.STM32F4xx_DFP.2.12.0`。
- 库依赖：工程目录内的 `CORE`、`FWLIB`、`SYSTEM`、`DMP` 等目录；其中 `libmpllib.lib` 为已有库文件。

### 编译与下载

1. 在 Keil 中分别打开以下文件：
   - `3.stm32代码/1.主控/USER/MPU9250.uvprojx`
   - `3.stm32代码/2.从控/USER/MPU9250.uvprojx`
2. 在工程配置中选择 `STM32F407VGTx`，配置 ARMCC 和器件包。工程目标名称为 `MPU9250`，输出名称为 `MPU6050`。
3. 对两个工程分别执行 `Rebuild`，完成编译。输出路径配置在各自的 `OBJ` 目录中。
4. 依据实物连接配置调试器和下载方式，将两个固件分别下载到相应的主控板与从控板。
5. 打开 `USER/main.c` 查看初始化与任务入口，结合 `HARDWARE` 下的模块实现核对执行器和通信连接。

两个工程中的部分中文注释采用 GBK 编码，阅读时可选择 GBK / 简体中文编码。

## 视觉程序

### 文件与平台

入口为 [`4.视觉代码/main.py`](../4.视觉代码/main.py)。程序使用 MaixPy 的 `camera`、`display`、`image`、`nn`、`uart` 和 `app` 接口，加载 YOLOv5 模型，运行时需要兼容 `.cvimodel` 的 MaixCAM / MaixCAM-Pro 设备环境。

本包提供推理程序、模型描述与已转换的模型文件，便于在设备端部署目标检测。平台与部署方式参考 [MaixPy 官方入口](https://wiki.sipeed.com/maixpy/en/)和 [MaixPy 官方模型部署说明](https://github.com/sipeed/MaixPy/blob/main/docs/doc/en/ai_model_converter/ai_model_deploy.md)。

### 部署步骤

1. 使用 MaixVision 连接兼容的视觉设备。
2. 在设备文件管理器中创建 `/root/models/maixhub/188743/` 目录，将 `model_188743.mud` 与 `model_188743.cvimodel` 一起上传到该目录。
3. 保留两个模型文件的名称；`.mud` 中的 `model` 指向同目录下的 `.cvimodel`。
4. 在 MaixVision 中打开 `main.py`，核对模型加载路径和串口设备 `/dev/ttyS0` 是否与实物一致，再在设备端运行。
5. 将目标置于摄像头视野内，观察画面中的检测框、类别名、置信度及控制台的 `Sent: 55` 输出。串口接收工具应按十六进制查看字节 `55`。

### 程序中已记录的参数

| 参数 | 当前值 |
| --- | --- |
| 模型加载路径 | `/root/models/maixhub/188743/model_188743.mud` |
| 模型类型 | `yolov5` |
| 模型标签 | `white` |
| 检测置信度阈值 | `0.5` |
| IoU 阈值 | `0.45` |
| 串口设备 | `/dev/ttyS0` |
| 波特率 | `9600` |
| 检测到目标后的输出 | 原始字节 `0x55` |

视觉程序依次完成图像采集、模型推理、检测结果绘制和串口信号输出。检测画面与串口输出可分别用于观察 AI 感知结果和通信过程。

## 串口屏工程

1. 使用兼容的陶晶驰串口屏编辑软件打开 `5.串口屏代码/串口屏代码.HMI`。
2. 按 HMI 工程内的设备配置设置屏幕型号、分辨率、方向及串口参数，选择与实物匹配的设备。
3. 查看页面、按钮事件与串口发送指令，执行编译和软件调试。
4. 按屏幕型号支持的下载方式将编译结果写入串口屏，连接 STM32 主控后检查触控指令与状态显示。

设备设置参考[陶晶驰官方资料中心](https://wiki.tjc1688.com/start/ide_introduce/ide_introduce13.html)。

## 串口接口说明

以下引脚来自对应串口初始化代码的 `GPIO_PinAFConfig`，波特率来自两个 `main.c`；使用时仍应与硬件设计文档和实物连接核对。表内引脚均为 STM32 一侧的发送与接收引脚。

| 连接 | STM32 串口 | TX / RX | 波特率 |
| --- | --- | --- | --- |
| 串口屏与主控 | 主控 USART1 | PB6 / PB7 | 9600 |
| 主控与从控 | 主控 UART5 | PC12 / PD2 | 230400 |
| 从控与主控 | 从控 UART4 | PC10 / PC11 | 230400 |
| 下摄像头与从控 | 从控 USART1 | PB6 / PB7 | 9600 |
| 上摄像头与从控 | 从控 USART2 | PD5 / PD6 | 9600 |

表中串口初始化均为 8 数据位、1 停止位、无校验。主控 TX 对接从控 RX，从控 TX 对接主控 RX；外围设备连接以实物引脚、电平和供电要求为准。

串口处理入口位于从控的 `HARDWARE/USART1.DMA/usartdma.c`、`HARDWARE/USART2.DMA/usart2dma.c` 及板间通信模块。视觉程序的输出为 `0x55`；从控 USART1 的事件分支包含 `0x10`、`0x11`、`0x20`、`0x21` 等字节，USART2 的事件分支包含 `0x01` 至 `0x04`。具体事件映射与接线按配套原型配置组织。

联调建议顺序为：分别验证串口屏、视觉推理与两个控制工程，再验证主从控通信，最后按实物操作流程检查视觉输入到执行机构的响应。机械臂、加热和消杀装置的动作测试应在配套设备的测试条件下进行。
